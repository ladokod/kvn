# Проверка KVN на Android 16

Пользователь уже подтвердил работу новой версии на своём телефоне. Ниже —
инструкция установки и расширенной проверки; сборка APK сама по себе не заменяет
проверку пользовательского трафика.

1. Скачать KVN-0.2.0-arm64.apk из GitHub Releases или собрать по README. Не использовать
   x86_64 artifact на смартфоне. Временная CI-подпись; при конфликте подписи потребуется
   удалить старую сборку (сохранённые реквизиты при этом удалятся).
2. Выключить Husi и другие VPN. В KVN ввести только домен VDS, логин и пароль.
   Сервер, Caddy и DNS-записи не менять. Реквизиты не прикладывать к отчётам.
3. Подключить и разрешить системный VPN. «Туннель создан» означает только TUN.
   Долгое нажатие KVN открывает необязательную HTTPS-проверку. NET12/EPERM здесь
   не доказывает, что браузер или Telegram лишились интернета.
4. Проверить в отдельном браузере публичный IP (должен совпасть с VDS), IPv4 и
   IPv6, несколько сайтов с CSS/картинками, YouTube (видео 1080p, перемотка),
   Telegram (сообщения и загрузка файла). Сравнить с Husi на том же телефоне,
   сервере и физической сети. Записать точную версию Husi и тип его Naive-профиля:
   встроенный outbound или внешний плагин. Текущая итерация KVN использует встроенный.
5. Загрузить HTTPS-файл >=100 MiB из доверенного источника, сверить размер/хеш;
   повторить 8 параллельных загрузок. Не ограничиваться открытием главной страницы.
6. Повторить 20 включений/отключений; отдельно отключить во время подключения.
   Свернуть на 30 минут, выключить экран, открыть снова; перезапустить Activity.
   Проверить Wi-Fi -> мобильная сеть -> Wi-Fi, временную потерю сети.
7. С неверным паролем проверить отсутствие direct fallback: сайты должны перестать
   загружаться, а IP не должен незаметно стать физическим. Ядро может создать TUN
   до первой попытки авторизации, поэтому нейтральный статус здесь ожидаем.
8. При остановке ядра работающая служба удерживает TUN; явное «Отключить» возвращает
   обычную сеть. При убийстве всего процесса Android может убрать VPN: для защиты
   в таком случае включить системные Always-on VPN и «Блокировать без VPN».
9. Проверить отсутствие реквизитов в logcat и приватных stderr.log. Не публиковать
   полный logcat без локального просмотра. Приложение логи никуда не отправляет.

В отчёте: модель, Android build, версия APK/commit, тип сети, результаты каждого
пункта, длительность и частота сбоев. Не считать все пункты этого расширенного checklist измеренными только по общему сообщению об успешной работе.
UDP-over-TCP выключен: обычный Caddy Naive не является sing-box UoT-сервером.
QUIC/другой UDP после DNS отклоняется; проверяется TCP fallback приложений.
